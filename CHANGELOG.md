## [Unreleased]

### Added

- **Nostr round-trip (send → relay → receive)**
  - `NostrRelay` now runs a background listener task per connection — the sole reader of the socket — dispatching `EVENT` frames to subscription callbacks, `OK` frames to publish acknowledgement futures, and `EOSE`/`NOTICE` for logging; the listener reconnects with exponential backoff and re-sends stored subscriptions until `disconnect()`.
  - `NostrAdapter` uses one persistent background event loop thread for its lifetime (`_ensure_loop`/`_run`); all relay I/O is marshalled onto it instead of creating and closing a loop per call.
  - `NostrAdapter.connect()` establishes the inbox subscription automatically, so events addressed to a stored identity are persisted at boot with no further calls (`main.py` `connect_all()` now yields a working receive path).
  - Event-id deduplication on persist: relays replay stored events on every `REQ`, so each event id is appended to the mailbox JSONL exactly once (ids loaded from the existing file on first use).
  - `fetch_records()` on the adapter exposes raw mailbox records with full bodies (the `Message` projection only carries a 140-char preview).
  - New `tests/nostr/test_roundtrip.py`: end-to-end send/receive against an in-process fake NIP-01 relay (publish → ACK → fan-out → decrypt → persist → replay dedup); Nostr suite now 80 tests.
- **Unified inbox**: `/get-mailbox` merges an account's IMAP and Nostr mail into one list sorted newest-first (IMAP-side failures degrade to Nostr-only when a Nostr identity exists; the Nostr branch no longer returns early), with a total across both transports.
- **Delivery-route metadata and UI**: `Email.route` (`gateway` = conventional IMAP/SMTP, `direct` = native Nostr identity ↔ native Nostr identity, `relay` = Nostr transport carrying a conventional address), `Email.source` typed on the client; `RouteBadge` rendered in mailbox rows and the reading pane (`emailDeliveryRoute()` prefers the backend value, sender heuristic only as fallback), plus Direct / Via relay / Via gateway filter chips wired to the existing `routeFilter` store.
- **Advanced search** (`SearchPanel`): From / To / CC / Subject / has-words / doesn't-have / since / before / has-attachment / unread / starred, serialized as `SearchCriteria` through `MailboxController.getMailbox`; the backend applies it to IMAP `SEARCH` and filters local Nostr records with the same criteria (date and flag aware); active search shows as a chip and survives Refresh/Clear.
- **Full-fidelity mail rendering** (reading pane, issues 1–4/8):
  - Opening a message now fetches its full content via `GET /get-email-content` (cached per uid for instant reopen; Nostr records and failed fetches fall back to the list-preview body) and renders it in a sandboxed `<iframe srcdoc>` instead of dumping server-side-stripped preview HTML into the page.
  - Bodies are sanitized with DOMPurify (scripts/event handlers stripped, `iframe`/`video`/`audio` and safe URLs kept), plain-text messages are escaped into a wrapping `<pre>`, and remote images, embedded video/audio players, `cid:` inline images and HTML/CSS styling render isolated from the app with an auto-height reporter (no inner scrollbar).
  - Attachment chips (name + size) with working downloads: the backend now decodes attachment parts to raw bytes and re-encodes them base64 (`BODY.PEEK`, binary-safe), fixing downloads that silently corrupted binary files through UTF-8 decoding.
- **Smart transport send (issues 5–6)**: `POST /send-email` takes a `transport` field (`auto` | `email` | `nostr`) and splits recipients per address type — npub/64-hex recipients go out over the Nostr adapter, everything else over SMTP — so one compose can reach mixed audiences, an existing Nostr identity no longer hijacks conventional sends, and forced modes validate mismatches ("npub recipients can only be reached over Nostr…"). Responses report each leg (`SMTP: … | Nostr: …`).
- **Split Send button (compose)**: main button sends with the current transport; the caret opens a menu (Smart routing / Email (SMTP) / Nostr) with hints and a selected check, plus client-side validation per forced mode. Sends always go through the unified `/send-email` (the compose-specific `/nostr/send-email` fetch path was removed from the client).
- **Settings modal** (mockup F3): centered modal with a w-248 dark left nav and four tabs — **Inbox** (theme, notifications, read receipts), **Account** (node id + copy, recovery phrase, key rotation, sign out, delete identity), **Nostr** (npub + copy, live relay status list with connect counts via `/nostr/relays`, transport summary), **Signature** (plain-text signature saved locally). Opened from the sidebar gear, the profile menu, and the command palette ("Go to settings") instead of the old full-page view.
- **Reading-pane label chips** (mockup F2): dimmed "Add label" button opens an inline input; chips render as `#373737` pills with a 14px × remove button. Labels are session-local, keyed per message uid, so reopening keeps them.
- **Search palette** (mockup F14): the sidebar Search row now opens a 450px popover (input + live results over the current folder: unread dot, sender/subject/snippet, time; empty-state hints) instead of swapping into an inline input; picking a result opens the reading pane and clears the query. Selection moved into the nav store (`selectedEmail`/`selectEmail`) with a shared `openEmailInPane()` helper so list rows and the palette share open+mark-read behavior; row-display helpers moved to `lib/mailbox/display.ts`.

### Fixed

- **App freeze ("loading message… for minutes") under concurrent requests**: the IMAP client shared one socket across FastAPI worker threads with no synchronization; a slow `UID SEARCH ALL` (60s read timeout) poisoned the makefile ("cannot read from timed out object") and `handle_idle()` waited on its in-process event with **no timeout**, so one wedged connection blocked every later request forever. All command transitions (availability NOOP, `done`, `IDLE` send/release, the optimized-lifecycle raw IDLE region) are now serialized on a per-connection `RLock`, `handle_idle` waits are bounded (30s) with idle state always restored, timeout-like errors poison the NOOP cache (`_note_connection_error`) so the next check reconnects, and criteria searches no longer clobber the uid-search cache (only `ALL` queries record baselines — avoids forced full-folder re-searches after every advanced search).
- **Recover identity silently minted a different npub**: `/nostr/register-identity` echoed the client-supplied npub (sent as `""` by the recovery flow), so recovered identities stored an empty address. The server now always derives the npub from the nsec (`npub = identity.public_key_bech32`) — in the register response and in `store_identity` persistence — so stored addresses stay NIP-19-valid even if a caller passes a stale value.
- **npub/nsec were not NIP-19-comparable with other Nostr clients**: `identity.py` computed checksums with the **bech32m** constant (`0x2bc830a3`) and prefixed a witness-version byte, producing 64-character strings no standard client can decode (real NIP-19 = plain bech32, constant `1`, 63 characters, no witness version). Encoding/decoding now uses plain bech32 with mixed-case rejection and strict 32-byte payloads; covered by new interop tests (independent BIP-173 reference implementation cross-check, length assertion, bech32m-checksummed string rejection).
- **Reply/forward to Nostr senders prefilled an empty recipient**: `extractEmailAddress()` returned `""` for bare npubs/hex keys (no `<…>` group, no `@`); it now recognizes `npub1…` and 64-hex values.
- **No identity hijack on send**: an account with a registered Nostr identity sent *every* message (including plain email) through the relay adapter; SMTP is now the default leg for non-npub recipients (see Added → Smart transport send).

- **Sending stopped working permanently after one failed send**: a Gmail timeout mid-send (`451 4.4.2`) left the SMTP socket closed, and nothing ever re-established the session — the connection check only NOOPs IMAP — so every subsequent compose attempt failed instantly with `please run connect() first` until the app was restarted. `SMTPManager` now keeps its credentials, restores the session before sending when the socket is gone, and reconnects + retries once on a dead session or a transient 4xx server response (4xx means the message was not accepted, so the retry cannot duplicate it).

- **Only the first page of mail ever loaded**: mailboxes fetch a small page (default 10 messages) and the new client had no pagination, so folders with more mail silently showed just the first page. The list now fetches the next IMAP page when scrolled near the bottom (and keeps fetching until it fills the viewport), merging pages with uid/message-id dedup and newest-first re-sort; the "loaded vs total" math counts only IMAP-side messages because the backend returns every Nostr record on each call.
- **Nostr receive path never worked** (three independent breaks): `NostrRelay.subscribe()` sent its `REQ` and returned with no task ever reading the socket, so subscription callbacks could never fire; every adapter operation created a fresh event loop and closed it (`connect`, `_publish_event`, `subscribe_for_messages`), leaving opened WebSockets bound to dead loops while `status.connected` still read `True`; and nothing called `watch()`/`subscribe_for_messages()` anyway. Fixed by the listener task, the persistent adapter loop, and auto-subscribe on connect (see Added).
- **NIP-04/NIP-44 decryption always failed**: the sender derived the recipient's X25519 public key by hashing their Ed25519 *public* key as if it were a seed, so both sides computed shared secrets that agreed with nothing and every decrypt ended in "Invalid padding bytes". The new `_x25519_public_from_ed25519_public()` performs the proper Edwards→Montgomery map (`u = (1+y)/(1-y)`), which provably matches the seed-derived key for the same identity; both encryption modes now round-trip (covered by the new test).
- **Nostr accounts could never see IMAP mail**: `/get-mailbox` returned from the Nostr branch before the IMAP path ran, so an account with a Nostr identity showed only Nostr mail (or nothing). The branch is now a merge of both transports.
- **Nostr mailbox fetch crashed**: the old branch constructed `Email` with missing required fields (`message_id`, `receivers`) and an unknown `has_attachments` keyword, raising `TypeError` (surfaced as the generic fetch error). Records are now projected through `_nostr_record_to_email()` with full fields.
- **Unawaited coroutine on Nostr unsubscribe**: `/nostr/subscribe/{account}` called `relay_pool.unsubscribe_all(sub_id)` without `await`, so subscriptions leaked ("coroutine was never awaited"); the adapter now exposes a synchronous `unsubscribe()`.
- "Email address already exists" but no account visible: accounts whose login failed land in the backend's *failed* list, and the landing accounts step only rendered *connected* accounts — failed ones were stored yet invisible, leaving no way to see or retry them. The table now lists failed accounts (marked "Failed to connect", tinted), matching the legacy client.
- Re-adding a stored-but-unconnected account was a dead end: `/add-account` rejected any stored address outright. It now only rejects accounts that are already connected ("This account has already been added"), and otherwise reconnects with the supplied password, updating the stored credentials on success — so retrying with a corrected password actually works.
- Silent IMAP failure: `Openmail.connect()` ran IMAP/SMTP setup in threads with no error handling and returned "Connected successfully" unconditionally, so a failed login still reported add-account success and every folder fetch then failed with "IMAP connection is not established". Thread exceptions are now captured and returned as `(False, message)`, and both add-account and mailbox-init failures surface the server's real error in the message modal (`details`).
- User-friendly connection errors: auth failures now show "Wrong email address or password…" (with a Gmail app-password hint) and network failures show a plain connectivity message, instead of raw IMAP/SMTP traces (`AUTHENTICATIONFAILED`, `535 … gsmtp`); the technical details are written to the server log.
- Fresh-install boot crash: the client's directory creation was non-recursive, so a missing parent (`os error 3`) aborted boot the first time real Tauri fs APIs were used — `mkdir` is now `recursive: true` (backend already used `os.makedirs`).
- Tauri mock gating: Tauri 2 sets `TAURI_ENV_PLATFORM` (not the Tauri 1 `TAURI_PLATFORM`) when spawning hooks, so the desktop app was bundling browser mocks — window controls were silent no-ops. `next.config.ts` now checks both names, and window/theme-listener failures are logged instead of swallowed.
- Duplicate toast React keys: `generateRandomId()` now returns a monotonic, collision-free id instead of bare `Date.now()`.
- Double boot under React StrictMode: app boot is guarded by a module-level promise so `PreferenceManager.init()` runs once per page load.
- Tailwind v4 semantics: `max-w-xl` resolves to 1024px (container scale) vs legacy 576px — command palette pinned to `max-w-[576px]`.
- Static modals (message/confirm) now position above the fixed compose overlay (`position:relative; z-index:1`).
- Shared-store deep mutations no longer bypass React: all `SharedStore.*` writes (accounts, failed accounts, folders, mailboxes, hierarchy delimiters, recent-emails channel, failed-folder/mailbox lists, flag marks, unsubscribe) now use top-level reassignment so the zustand proxy notifies subscribers; legacy `.push()`/index writes updated state silently without re-rendering.
